# 릴리즈 노트 v0.2.1

**발행일**: 2026-04-20
**카테고리**: Infrastructure / Reliability

## 🚀 개요
이번 릴리즈는 서버 이중화(Active/Standby) 구성의 안정성을 강화하고, 인프라 환경을 표준화하여 라우팅 문제를 근본적으로 해결하는 데 집중했습니다.

## 🔍 문제 분석 (Root Cause Analysis)
기존 이중화 환경에서 다음과 같은 두 가지 핵심 문제가 발견되었습니다:

1. **인프라 파편화 (Infrastructure Drift)**:
   - 홈서버(Active)는 Docker 컨테이너 내에서 `cloudflared`를 실행한 반면, 대기서버(Standby)는 macOS의 Homebrew 서비스로 직접 실행했습니다.
   - 이로 인해 대기서버는 Docker 내부 네트워크 전용 호스트명(예: `http://grafana:3000`)을 해석하지 못해, 대기서버로 트래픽이 흐를 때 502 Bad Gateway 에러가 발생했습니다.

2. **환경 변수 관리 누락**:
   - `GRAFANA_ADMIN_PASSWORD` 변수가 `.env` 파일에서 누락되어 대기서버의 모니터링 컨테이너들이 정상적으로 시작되지 못했습니다.

## 🛠 해결 방안 (Resolution)

### 1. 인프라 표준화 (Dockerized Cloudflared)
- 대기서버의 `cloudflared`를 네이티브 서비스에서 Docker 컨테이너로 전환했습니다.
- 이를 통해 대기서버도 홈서버와 동일한 Docker 브리지 네트워크를 공유하게 되어, 서비스 이름을 통한 내부 라우팅이 가능해졌습니다.

### 2. 라우팅 설정 최적화
- `cloudflared/config.yml`을 표준화하여 `review-server:8080`과 같은 서비스명으로 연결되도록 개선했습니다.
- 이제 트래픽이 어느 서버(Active 또는 Standby)로 가더라도 각자의 Docker 환경 내에서 올바른 목적지를 찾아갑니다.

### 3. 구성 자동화 및 검증
- `docker-compose.standby.yml`을 확장하여 `cloudflared`와 `grafana`를 포함시켰습니다.
- `deploy-standby.sh`를 통해 한 번의 명령으로 모든 스택이 표준화된 환경에서 배포되도록 자동화했습니다.

## 📈 기대 효과
- **고가용성(HA) 실현**: 홈서버 다운 시 대기서버가 즉시 트래픽을 넘겨받아도 502 에러 없이 무중단 서비스가 가능합니다.
- **운영 일관성**: 두 서버가 동일한 배포 방식을 사용하므로 관리 효율성이 증대되었습니다.
