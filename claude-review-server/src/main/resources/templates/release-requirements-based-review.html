B

변경 전 — 과제 요구사항을 몰랐던 AI

수강생이 Lettuce 기반 Lock을 구현했습니다 
// 과제 요구사항: Lettuce로 Redis Lock 구현 (Redisson 금지)
public boolean tryLock(String key, String value, long ttl) {
    return redisTemplate.opsForValue()
        .setIfAbsent(key, value, Duration.ofMillis(ttl));
}
기존 AI 리뷰 — 과제와 충돌하는 권고 
### 🟡 개선 제안

**Redisson 도입을 권장합니다**
현재 Lettuce 기반 Lock은 재시도 로직이 없어 일시적인 경합 상황에서
정상적인 요청마저 차단됩니다. Redisson의 tryLock(waitTime, leaseTime)을
사용하면 더 안정적인 Lock 관리가 가능합니다.

→ 과제에서 Lettuce 사용 필수, Redisson 사용 금지라고 명시되어 있음
→ AI가 과제 요구사항을 몰라서 과제와 반대되는 권고를 함

A

변경 후 — 과제 요구사항을 아는 AI

동일한 코드에 대해 과제 관점에서 리뷰 
### 📋 과제 요구사항 준수 여부

**Lettuce 기반 Redis Lock** — 준수 ✅
- SETNX + TTL 패턴으로 Lock 획득 및 자동 만료 구현 확인
- 과제에서 Redisson 사용 금지이므로 Lettuce 선택은 올바릅니다

**개선 권장:**
- Lock 해제 시 UUID 검증 + Lua Script로 원자적 해제가 필요합니다
- 현재 `delete()`만 사용 중인데, 다른 스레드의 Lock을 해제할 위험이 있습니다
Redisson을 사용한 경우 — 자동 지적

과제에서 금지하는 기술을 사용하면 🔴 필수 수정으로 즉시 지적합니다.

### 📋 과제 요구사항 준수 여부

**🚨 Redisson 사용 감지 — 과제 요구사항 위반**
과제에서는 Lettuce 기반 Lock을 요구하며, Redisson 사용을 금지합니다.
필수 기능에서는 Lettuce + SETNX + TTL + UUID + Lua Script로
다시 구현해야 합니다.
